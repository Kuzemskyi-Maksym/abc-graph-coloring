# abc-graph-coloring

Бджолині алгоритми (ABC) для задачі розфарбування графа: порівняння існуючих модифікацій і розробка власної. Наукова робота, керівник: М. Головченко (КПІ ім. Ігоря Сікорського, ФІОТ).

**Задача:** розфарбувати вершини неорієнтованого графа так, щоб суміжні мали різні кольори, і мінімізувати кількість кольорів.

## Запуск
Python 3.10+, без сторонніх залежностей.

```bash
python run.py --time 3 --seeds 5 --exact 60 --out results/run.csv data/*.col
```

Параметри: `--time` (секунд на запуск), `--seeds` (кількість запусків), `--algs` (через кому, за замовчуванням усі), `--procs` (процеси).

## Структура
- `abc_gc/graph.py`: читання DIMACS `.col`, перевірка правильності розфарбування
- `abc_gc/heuristics.py`: greedy first-fit, DSATUR, RLF
- `abc_gc/exact.py`: **точний метод**: backtracking (branch and bound) у стилі DSATUR. Вершина: максимальна насиченість, при рівності більший степінь у непофарбованому підграфі. Порядок кольорів: перший / найуживаніший. Нижня межа: жадібна кліка. Якщо пошук завершився, знайдене k = хроматичне число (доведено)
- `abc_gc/bees.py`: існуючі модифікації та еталони
  - `vertex_bee`: Chahkandi & Mirzaei (з лекції): вершина = джерело їжі, нектар = степінь
  - `site_bee`: версія з лекції: ділянка = ціле розфарбування, фуражири спорожнюють останній колір
  - `habc`: Fister Jr., Fister, Brest (2012), адаптовано на мінімізацію k
  - `tabucol`: TabuCol (спрощений), не-бджолиний еталон
  - `own_abc`: перша чернетка власної модифікації (12.10), лишена для порівняння
- `abc_gc/mods.py`: **власні модифікації**
  - `own_a` (A): вершина = джерело, але нектар = кількість ще не пофарбованих сусідів, вершини обираються по одній рулеткою, правило «найуживаніший колір»; кожне побудоване розфарбування стає джерелом, фуражири спорожнюють його останній колір (версія 1 з лекції), спостерігачі підсилюють кращі джерела, розвідники будують нові
  - `own_b` (B): ділянка = розфарбування з фіксованим k−1, бджоли роблять табу-ходи min-conflicts; джерела стартують з різних конструкцій (DSATUR, RLF, випадковий greedy, конструкція A), розвідники перезапускаються з нової конструкції
  - `own_c` (C): адаптивний вибір правил: джерело = правильне розфарбування, кожна бджола обирає один із 4 операторів (спорожнити останній колір, ланцюг Кемпе, iterated greedy Калберсона, випадкове перефарбування) з імовірностями, що оновлюються за успіхом оператора
- `abc_gc/registry.py`: усі алгоритми й абляції, які порівнюються
- `run.py`: однаковий бюджет часу на кожен запуск, `--exact T` додає точний метод з лімітом T секунд
- `data/`: 18 графів DIMACS (копія з [dynaroars/npbench](https://github.com/dynaroars/npbench))
- `results/`: сирі результати прогонів

## Відхилення від оригінальних статей
- **HABC:** декодер first-fit за порядком ваг (у статті DSatur); мета мінімізувати k замість фіксованого 3-розфарбування; ймовірність спостерігачів рахується за якістю (у статті формула (5) рахує за кількістю конфліктів).
- **site_bee:** «заміна кольору вершини з суміжною» трактується так: вершина з останнього кольору бере колір c сусіда u, якщо u її єдиний сусід кольору c, а u переходить в інший нижчий колір.

## Статус
- **2026-10-12**, перший прогін (3 с, 5 запусків): чернетка `own_abc` не краща за TabuCol, бджолина структура в ній нічого не додає.
- **2026-10-19**, другий прогін (3 с на метаевристику, 5 запусків; точний метод до 60 с на граф): додано точний backtracking і модифікації A, B, C.
  - Точний метод довів оптимум на 9 із 18 графів.
  - B: найкращий середній ранг (4.61), середнє відхилення від найкращого відомого k 10.5 % проти 11.8 % у TabuCol.
  - C: 11.1 %, але без адаптації (рівні ймовірності операторів) не гірше, тож адаптивний вибір поки нічого не дає.
  - A: 23.8 %, значно краще за базову версію з лекції (28.6 %); головний внесок дають фуражири (без них 33.5 %).
  - Результати попередні: для висновків потрібно 30 запусків і статистичні тести.
